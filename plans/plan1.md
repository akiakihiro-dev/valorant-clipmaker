# plan1: Valorant ハイライトクリップ自動生成ツール MVP実装計画

## 1. 目的

NVIDIA ShadowPlay等の「インスタントリプレイ」機能で保存された、直前数十秒〜1分程度の `.mp4` クリップを
入力として、その中に含まれるkillシーンだけを自動でカット編集し、ハイライトクリップとして出力するツールの
MVPを実装する。

すでにMedal.tv・Outplayed・Insights Capture・Powderなど「プレイ中に常駐してキルを自動検出・録画する」
無料ツールは存在するため、本ツールは差別化として「**すでに保存済みの録画済みクリップに対して後処理で
ハイライト編集をかける**」「**完全ローカルで動作する**」という方向で作る。

`.vrf`（リプレイ/デモファイル）はValorantが公式に出力する機能を持たず、フォーマットも非公開で
実装リスクが高いため採用しない。入力は録画済みmp4のみとし、画面上のキルフィード表示からキルイベントを
検出する。

MVPのスコープは「動くこと」を最優先とし、自動編集・BGM合成・字幕付けなどの拡張機能は対象外とする。

## 2. 入出力

- 入力
  - `.mp4` ファイル（複数）: NVIDIA ShadowPlay等のインスタントリプレイで保存された、
    1本あたり数十秒〜1分程度の録画クリップ。プレイヤー視点でキルフィードがHUD上に表示されているもの。
- 出力
  - 各入力クリップから、killシーンのみを切り出した `.mp4` ハイライトクリップ（1入力につき0〜1出力）

## 3. 処理パイプライン（MVP）

1. **フレーム抽出**
   - 入力mp4から一定間隔（例: 5〜10fps相当）でフレームをサンプリングする。
   - 画面上のキルフィードが表示される領域（右上付近）をROI（切り出し範囲）としてクロップする。
     ROI座標は解像度・HUD設定に依存するため、設定ファイルやパラメータで指定可能にする。

2. **キル検出**
   - ROI画像に対し、キルフィードに現れる特徴的なアイコン（撃破表示のクロスヘア/武器アイコン等）を
     テンプレートマッチングで検出する方式をMVPの主軸とする。
     - OCR（プレイヤー名・武器種の読み取り）は解像度やフォントレンダリングの影響を受けやすく
       実装難易度が高いため、MVPでは見送り将来拡張とする。
   - 検出結果として「キルが発生した時刻（クリップ内の相対時間）」のリストを得る。

3. **カット区間の決定（ルールベース）**
   - 検出したキル時刻列を、以下のルールでグルーピングし、ハイライト区間を決定する。
     - kill間隔が3秒未満の場合は同一グループ（連続killシーン）とみなす。
     - kill間隔が3秒以上空いた場合はグループを分割する
       （直前killの1秒後まで／次killの2秒前からを、それぞれ別グループの終了・開始とする）。
   - 各グループについて、区間の開始を「グループ内最初のkillの2秒前」、終了を
     「グループ内最後のkillの1秒後」とする。
   - 1つの入力クリップから、キルが検出されなければ出力0件、複数グループに分かれればそれらをつなげた一つのmp4を出力とする

4. **クリップ切り出し**
   - `ffmpeg` を用いて、各グループの区間を入力mp4から切り出す。
   - 切り出しは再エンコードなし（`-c copy`）を優先し、必要に応じて再エンコードにフォールバックする。

5. **出力**
   - 出力クリップを保存し、出力する。
   - 複数の入力クリップをバッチ処理し、出力ディレクトリにまとめて出力できるようにする。

## 4. 未解決事項（実装前に調査・決定が必要）

- キルフィードのROI座標・解像度依存性
  - 解像度やアスペクト比、HUDスケール設定によってキルフィード表示位置が変わるため、
    サンプル映像で座標を確認し、可変にできる設計にする必要がある。
- テンプレートマッチングの検出精度
  - 実際のサンプルクリップで誤検出・検出漏れがどの程度発生するか検証が必要。
  - 精度が不十分な場合、OCRや簡易的な画像分類モデルへの切り替えを検討する。
- カット区間ルールの妥当性
  - 「2秒前／1秒後／3秒以上で分割」の閾値は仮決めであり、実際のクリップで見た目を確認して調整する。
- インスタントリプレイの保存トリガー
  - このツールはユーザーが手動（またはNVIDIA側の何らかのトリガー）で保存したクリップを後処理する前提。
    保存トリガー自体の自動化（キル時に自動保存させる等）は本ツールのスコープ外とする。

## 5. ディレクトリ構成（案）

```
valorant-clipmaker/
├── src/
│   ├── kill_detector.py       # フレーム抽出・ROI切り出し・キル検出（テンプレートマッチング）
│   ├── highlight_detector.py  # カット区間の決定ロジック（グルーピング・バッファ計算）
│   ├── clipper.py             # ffmpegによる動画切り出し
│   └── main.py                # パイプライン実行エントリーポイント（複数クリップのバッチ処理）
├── tests/
│   └── ...
├── plans/
│   └── plan1.md
└── README.md
```

## 6. タスク分解

1. サンプルクリップからキルフィードのROI座標を確認し、テンプレート画像を用意する
2. フレーム抽出・ROI切り出し処理の実装（`kill_detector.py`）
3. テンプレートマッチングによるキル検出の実装・精度検証
4. カット区間決定ロジックの実装（`highlight_detector.py`）
5. `ffmpeg` 呼び出しによるクリップ切り出し実装（`clipper.py`）
6. パイプライン統合（`main.py`）: 複数の入力mp4を受け取り、ハイライトクリップ群を出力
7. サンプルデータでの動作確認・カット区間の見た目調整

## 7. スコープ外（MVP後の拡張候補）

- クラッチ判定（残り人数状況の推定、HPバーやミニマップ解析を含む）
- OCRによるキルフィードのプレイヤー名・武器種の読み取り
- 音声解析による検出精度の補強
- インスタントリプレイの保存トリガー自体の自動化
- クリップの自動結合・自動編集（トランジション、BGM、テロップ）
- GUI/Webインターフェース
